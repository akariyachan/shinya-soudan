## 再現・再生成

```sh
node tools/prove-reachability.js
node tools/prove-reachability.js --check
node tools/prove-reachability.js --replay=alone/A
node tools/prove-reachability.js --replay=alone/C
node tools/generate-branchmaps.js
node tools/generate-branchmaps.js --check
```

`--max-states=100000` と `--max-key-bytes=268435456` が探索の既定予算です。増減できますが、停止時点・実測件数も変わります。同じソースと予算からのJSON・資料生成は決定的です。証拠とソースのハッシュが合わない場合、生成器は古い判定の再利用を拒否します。

JSONの各witnessは初期seenThreads、全actions（カードIDと各メモのtake）、文言付きchoices、最終state、実際に評価した条件側を持ちます。番号や確率だけに依存せず、表示される選択列そのものを再生します。カードの非表示、余った入力、最終状態の不一致はエラーです。

## 対象と検証範囲

正常な初期状態からの選択肢とメモ回収／未回収。既読糸64集合を初期根として用意。UIの描画・待機・音はスタブ。ゲームの条件・採点・非同期進行は実エンジン。改変セーブ・DOMや実時間は対象外。

HTMLから読み込む現行storyだけを対象とし、v0/・v1/・tools/old/は除外します。runSteps/runScript/runVisitor/runFrameSeg/runScene/runPlain/playNight/morningLetters/playEpilogueはindex.htmlから関数本体を読み込みます。追加した観測フックとUI入力以外は実装の処理を実行し、既存の同期進行モデルを到達性の証明には使いません。既存モデルのランダム列は到達候補としてのみ利用し、すべて実エンジンでリプレイし直しています。

DOM描画、クリック座標、音、待ち時間、改変したセーブ、過去版のセーブ互換性は対象外です。ブラウザーのUI操作を網羅したという主張はしていません。未完了のDFSから全木網羅を主張することもありません。
